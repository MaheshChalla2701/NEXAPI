# Revenue Review — analytics app (development scaffold)

> **Status: development build on MOCK data.** The assignment brief's repository and raw data are not
> available yet. Every number this app currently shows is synthetic, generated by
> `pipeline/providers/mock.py`, and labelled as mock in the API and on every page. Nothing here is a
> finding about the assignment. The assignment deliverables (`UNDERSTANDING.md`, `DECISIONS.md`,
> `REPORT.md`, `agent-conversation/`) are deliberately **not** written yet.

A React frontend and a Python backend over a single SQLite database. The pipeline that fills the
database is replaceable: today a mock provider, later the real assignment pipeline. Backend and
frontend do not change when the provider does.

```
raw files ──► pipeline/ (Python) ──► var/app.db (SQLite, only DB) ──► backend/ (stdlib HTTP API) ──► frontend/ (React)
              provider: mock | assignment     validated on every build        read-only                 no metric maths
```

## Quick start

Requirements: Python 3.10+ (standard library only) and Node.js 20+ (tested with Node 22.12, npm 10.9).

```bash
# 1. Build the SQLite database (mock data for now)
python3 -m pipeline.build_db --source mock

# 2. Start the API on http://127.0.0.1:8000
python3 -m backend.server

# 3. In a second terminal: start the frontend on http://localhost:5173
cd frontend
npm install        # first time only
npm run dev        # Vite proxies /api to the Python server
```

Single-process alternative: `cd frontend && npm run build`, then `python3 -m backend.server` serves the
built app and the API together at http://127.0.0.1:8000.

### Tests and checks

```bash
python3 -m unittest discover -s tests -t .     # pipeline, API, analyst, number guard (21 tests)
cd frontend && npm run typecheck               # TypeScript strict mode
```

## What was added, and why

Python: **nothing**. The pipeline, API server, statistics helpers and optional AI adapter all use the
standard library (`sqlite3`, `http.server`, `urllib`, `statistics`). pandas/pyarrow are installed on
this machine and will be used by the real pipeline to read the raw files in chunks; the mock provider
doesn't need them.

Frontend (`frontend/package.json`, locked in `package-lock.json`; 23 packages installed in total):

| Package | Version | Why |
|---|---|---|
| `react`, `react-dom` | 19.3 | UI framework, as requested |
| `vite`, `@vitejs/plugin-react` | 8.3 / 6.3 | dev server with `/api` proxy and production build |
| `typescript`, `@types/react`, `@types/react-dom` | 5.9 / 19.x | type checking (dev only) |

Not added: router, chart library, UI kit, state library, CSS framework, icon set. Routing is a ~30-line
hash router (`src/lib/router.ts`); charts are hand-written SVG (`src/components/charts/`).

## Project layout

```
pipeline/
  schema.sql            SQLite schema = data contract every provider must fill
  build_db.py           build → validate → atomically replace var/app.db
  validate.py           integrity checks (bridge reconciles exactly, one unexplained bar, FKs, rates in 0–1 …)
  stats.py              difference in proportions / means with 95% CIs, sample-ratio-mismatch test
  providers/mock.py     deterministic synthetic data (seeded), every value tagged MOCK
  providers/assignment.py   stub that refuses to run until the real pipeline is written
backend/
  server.py             routing, input validation, JSON errors, static file serving
  api.py                one function per endpoint; read-only SQL
  config.py             env settings; secrets never leave the server
  analyst/              local rule engine, optional external adapter, mode router
frontend/src/
  pages/                8 pages (see below)
  components/charts/    Waterfall, Line, Bar, Funnel, CohortHeatmap, IntervalPlot, ChartFrame
  components/ui/        cards, KPI tiles, badges, tables, states, icons
tests/                  unittest suites
var/app.db              generated, git-ignored
```

Every chart has a title with units and period, a legend for 2+ series, hover/keyboard tooltips, a
**Table** toggle (no value is only reachable by hovering) and an **Explain** button that asks the analyst
about that chart. A consistent light-only interface is used regardless of operating-system theme or previously saved preferences.

## API

All `GET` endpoints return `{ "meta": {...data_source, is_mock, currency, periods...}, "data": {...} }`.

| Method | Path | Notes |
|---|---|---|
| GET | `/api/health` | liveness + whether the database exists |
| GET | `/api/meta` | run metadata + public analyst status (never the key) |
| GET | `/api/overview`, `/api/bridge`, `/api/onboarding`, `/api/pricing`, `/api/referrals`, `/api/data-quality` | page payloads |
| GET | `/api/retention?segment=all\|organic\|referred` | invalid values → 400 |
| GET | `/api/filters` | available segments, months, regions |
| GET | `/api/analyst/status`, `/api/analyst/suggestions` | |
| POST | `/api/analyst/ask` | `{"question": str (1–500 chars), "mode": "auto"\|"local"\|"external"}` |

The database is opened read-only (`mode=ro`), the server binds to 127.0.0.1 by default, request bodies
are capped at 8 KB, and unexpected errors return a generic 500 without internals.

## AI Analyst

**Local mode (default, no key, no network).** `backend/analyst/local_engine.py` maps a question to one
of ~16 intents (bridge drivers, unexplained remainder, each initiative, retention, sign-ups, data quality,
anomalies, comparisons, recommendations, chart explanations, metric definitions, next steps) and answers
from SQLite. Every answer carries evidence rows with their source table, a confidence statement,
limitations and next steps. It is a rule-based engine, not a language model, and the UI says so.
Questions it can't ground get an explicit "outside what I can answer" reply plus suggested questions.
It never generates a recommendation: it only reports what the `initiative` table holds (all `PENDING`
in mock mode).

**Optional external mode (off by default).** To enable it later:

```bash
export ANALYST_EXTERNAL_ENABLED=true
export ANTHROPIC_API_KEY=...            # read from the environment only; never sent to the browser
# optional: ANALYST_MODEL (default claude-opus-5-5), ANALYST_EFFORT (default medium), ANALYST_TIMEOUT_S
python3 -m backend.server
```

Or put the same keys in a local `.env` (git-ignored; see `.env.example`). The adapter
(`backend/analyst/external.py`) calls the Claude Messages API with `urllib`, so it adds no dependency.
It requests server-side refusal fallbacks (`fallbacks: "default"`). The model only rewrites verified
facts: it receives the database context plus the local answer, and **every number in its reply is
checked against that context**. If any number can't be traced, or the call fails, times out, is
refused or truncated, the local answer is returned with a notice saying why. The active mode is shown
in the sidebar, on the analyst page and on every answer.

## Connecting the real data

1. Put the assignment repository's `data/`, `dashboards/` and `scripts/` alongside this code (or point
   `--data-root` at it). Raw files are never modified.
2. Inspect the real files first. The assignment requires `UNDERSTANDING.md` to be handed in before
   substantive analysis starts.
3. Implement `pipeline/providers/assignment.py` so it fills every table in `pipeline/schema.sql` with
   `data_source = 'assignment'`. Read the ~20M event rows in bounded chunks and store only aggregates.
4. `python3 -m pipeline.build_db --source assignment`. The validator rejects the build unless the bridge
   reconciles exactly to the total change and has exactly one explicit unexplained bar.

The schema may need columns or tables the real findings call for. It was designed from the brief, not
from the data, so treat it as a starting point.

## Known limitations of this scaffold

- All figures are mock. Schema, metric definitions and chart set reflect the brief and will be revised
  once the real files are inspected.
- The mock bridge drivers, experiment results and data-quality statuses are random and mean nothing.
- The local analyst matches keywords; unusual phrasings may fall through to "outside what I can answer".
- No git repository exists in this folder yet. The assignment's own repository (with its history) is
  where this work should end up.
